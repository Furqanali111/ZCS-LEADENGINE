# Slice 2 CRM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add lead detail, an insert-only activity history, one follow-up date per lead, a suppression list, a drag-and-drop pipeline board and a dashboard on top of slice 1.

**Architecture:** Snapshot columns on `organizations` (`last_contacted_at`, `next_follow_up_at`) plus an insert-only `lead_activities` table guarded by a database trigger. Every lead-changing action writes one activity and updates the snapshot in one transaction. `suppression_list` has no foreign key to organizations. New FastAPI routers and Next.js pages follow slice 1 patterns.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, psycopg 3, Pytest on embedded Postgres (`pgserver`); Next.js App Router, TypeScript, Tailwind, shadcn/ui. No new dependencies: the board uses native HTML5 drag and drop, charts are plain divs.

**Spec:** `docs/superpowers/specs/2026-11-11-crm-design.md`

## Global Constraints

- Hard rules in `CLAUDE.md` apply: zero PHI, no auto outreach, never invent data, no conversion probability anywhere, no em dashes anywhere (code, comments, commits, docs).
- Fit score, priority and conversion rate are different things. The dashboard rate is recorded outcomes only, shown with numerator, denominator and date range.
- Activities are never updated or deleted: no API route, and a database trigger rejects UPDATE and DELETE.
- `suppression_list` has no foreign key to `organizations`.
- Statuses (existing `CRM_STATUSES`): new, researching, email_sent, called, follow_up_required, interested, meeting_scheduled, not_interested, converted, do_not_contact. Closed statuses: converted, not_interested, do_not_contact.
- Activity types: call, email, meeting, note, status_change, outcome. Outcomes: no_answer, spoke, interested, not_interested, meeting_booked, converted, other. `summary` max 2000 chars.
- Suppression kinds: npi, phone, email. Normalization: npi and phone digits only, email lower-cased and trimmed. Unique on (kind, value).
- Error shape stays `{"error": {"code", "message"}}` via `AppError`. Lists paginated.
- Migration 0004 revises 0003 and enables row-level security on both new tables (no policies, no FORCE).
- Conventional Commits, one-line subject, `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` trailer. Never push to `develop`. Branch `feature/crm-slice`.
- Backend tests use embedded Postgres, never the real database. Python 3.12, venv at `backend/.venv`.
- Update docs when routes or env change.

## Review Focus

- `PATCH /api/leads/{id}` with `{"next_follow_up_at": null}` clears the date, while an empty body or unknown field is 422 (explicit null is not "missing").
- Setting a status to the lead's current status writes no activity and no error.
- A search re-run that saves an NPI already on the suppression list does not reset it from `do_not_contact` to `new`.
- Phone suppression matches regardless of formatting: `(813) 671-0064`, `813-671-0064` and `8136710064` are one entry.
- Dashboard with zero contacted leads returns `rate: null`, and a `from` later than `to` is 422.
- Board `load more` past the last lead returns an empty list, not an error, and counts stay consistent after a drag.
- Logging an older call (earlier `occurred_at`) never moves `last_contacted_at` backwards.

## Shared contracts (used by several tasks)

```
ActivityIn   { type, occurred_at?: datetime, summary?: str<=2000, outcome?, next_follow_up_at?: date|null }
ActivityOut  { id, type, occurred_at, summary, outcome, from_status, to_status, created_at }
PATCH body   { crm_status?, next_follow_up_at?: date|null }   (at least one field, extra forbidden)
LeadOut      existing fields + last_contacted_at, next_follow_up_at, suppressed: bool
PipelineCard { id, name, city, state, organization_type, fit_score, priority, next_follow_up_at, last_contacted_at }
GET /api/pipeline?limit=20            -> { columns: [{ status, count, leads: [PipelineCard] }] }
GET /api/pipeline/{status}?offset&limit -> { status, count, leads: [PipelineCard] }
GET /api/dashboard/stats?from&to      -> { range: {from,to}, total, new_leads, critical_high, follow_ups_due,
                                           meetings_scheduled, converted, by_state: [{key,count}], by_specialty: [{key,count}],
                                           by_status: [{key,count}], recent_jobs: [JobOut], conversion: {converted, contacted, rate|null} }
Suppression  { id, kind, value, reason, created_at }  GET/POST /api/suppression, DELETE /api/suppression/{id}
```
